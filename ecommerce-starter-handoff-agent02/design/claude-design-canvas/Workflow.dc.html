Design workflow principles

  1. Mobile and desktop are drawn together for every screen, never desktop-then-shrink.
  2. Shared flows are designed once; brand differences live in tokens and composition (homepage, card, PDP).
  3. Every essential screen lists its states before it is drawn (loading, empty, error, success, disabled, validation, unavailable).
  4. One naming scheme across Claude Design components, tokens and React components (e.g. ProductCard/Compact ↔ ProductCard variant="compact").
  5. Prices, stock and statuses in mockups come from the same seeded dataset the React prototype will use.
  6. Accessibility is checked per milestone (contrast, focus order, target size), not only at M8.

Trade-offs taken in M0

Claude Design as the single design tool (owner decision D1): one source of record, no Figma export step; the cost is building component variants as tweakable artboards instead of Figma variants.
Reserve stock at order creation, not add-to-cart: avoids phantom holds from abandoned carts; the cost is a possible stock failure at the review step, which gets its own state.
Pagination over infinite scroll: crawlable and reachable pages; mobile still gets "load more".
Same-category comparison: meaningful shared attributes, at the cost of not comparing across categories.
Reviews display-only: no moderation tooling needed now.
