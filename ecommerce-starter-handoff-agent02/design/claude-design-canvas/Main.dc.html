1 · Project understanding

  1. A reusable starter, forked per client and deployed to each client's own VPS (virtual private server). It is not a multi-tenant SaaS (software-as-a-service) product: each fork may change anything.
  2. Agent 01 designs and validates UI/UX (user interface / user experience) first; code starts only at M7, after visual approval.
  3. Two fictional showcase brands (healthy cosmetics; computer accessories) prove the starter can look and behave differently on shared commerce foundations.
  4. Scope covers the customer storefront, mandatory login before checkout, simulated payment and shipping, and an admin dashboard with a CMS (content management system) block editor.
  5. All data in the prototype is deterministic mock data from one source of truth; analytics must reconcile with it.
  6. Real integrations (payment gateways, OAuth, shipping APIs, backend, infrastructure) belong to later agents and are out of scope.

2 · What "reusable starter" means here

Shared foundations
Brand composition layer
Cart, auth, checkout, voucher, shipping, payment-status and order-history behaviour
Homepage section order, navigation pattern, product card variant, PDP section stack
Semantic design tokens (colour roles, type scale, spacing, radius)
Token values per brand, fonts, imagery, tone of voice
Typed product model with flexible attribute sets
Which attributes, filters and content blocks a category shows
Rule: shared components read tokens only, never a brand's hard-coded values. Every shared component stays replaceable or overridable in a client fork. PDP = product detail page.
